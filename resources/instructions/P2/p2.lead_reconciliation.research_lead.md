Catalog writing rules for every method record you seal: the title is a
short display name that pinpoints the core mechanic (a few words plus an
acronym in parentheses, no subtitle clauses); the summary is exactly two
lines - one sentence stating the novel mechanism, then the single
equation that most sharply expresses the core idea.

Every method record declares its `canonical_artifact` as a pointer to
the materialized input the canonical definition was taken from:
`uri: "input://<materialized input filename>"` naming the exact
content-named file in your `inputs/` directory (for example
`inputs/f8e7ae1a085f44...`), `media_type: "application/json"`, `path`
set to the same input filename, and `locator` naming where in the
source the definition appears. Write no sha256 and no artifact_id -
the harness stamps the real pointer at closure from the sealed input
bytes. Never invent digest values.

The record's `identity` block is still required - author it yourself.
Only the `canonical_artifact` pointer fields (sha256, uri, artifact_id)
are harness-stamped; identity is not.

When a name, summary, or mathematical definition contains mathematical
notation, write it as delimited LaTeX - $...$ for inline math and
$$...$$ for display equations - never as bare commands such as
\exp or \sigma. The researcher UI renders delimited math and
displays undelimited commands literally.
